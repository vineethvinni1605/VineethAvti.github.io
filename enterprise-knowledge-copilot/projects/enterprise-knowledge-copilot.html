THE PROBLEM

How can an LLM answer questions using approved enterprise knowledge?

General-purpose language models can generate useful responses, but enterprise questions often need answers grounded in specific internal policies and documents.

Enterprise Knowledge Copilot uses Retrieval-Augmented Generation to retrieve relevant company knowledge before asking the language model to generate a response.

DOCUMENT PROCESSING

Preparing enterprise knowledge for retrieval.

The source document is divided into overlapping text chunks before retrieval.

500 CHARACTER CHUNK
100 CHARACTER OVERLAP

Overlap preserves context across chunk boundaries while keeping individual retrieval units relatively focused.

04

EMBEDDINGS

Moving beyond keyword matching.

Document chunks and user questions are converted into vector embeddings using the all-MiniLM-L6-v2 Sentence Transformer model.

This representation allows the retrieval layer to compare questions and policy content based on semantic similarity rather than exact keyword matches.

05

SEMANTIC RETRIEVAL

Retrieve the most relevant knowledge first.

Cosine similarity compares the question embedding against the document embeddings.

The three highest-scoring chunks are selected and assembled into the context supplied to the language model.

06

GROUNDED GENERATION

Retrieve first. Generate second.

Retrieved policy context is passed to an OpenAI language model together with the employee's question.

The generation instructions restrict the model to the supplied company knowledge. When the answer is unavailable, the system is instructed to say that the information could not be found.

07

EVALUATION

Testing grounded answers and unsupported questions.

TEST 01

Grounded Question

“How many PTO days can carry over?”

The system retrieved the relevant PTO policy and correctly answered that unused PTO may carry over up to five days.

TEST 02

Unsupported Question

“What is the company's dental insurance policy?”

Because dental insurance information was not present in the knowledge base, the system correctly returned the configured fallback response instead of inventing an answer.

09

LIMITATIONS

A working RAG prototype, not a production knowledge platform.

The current knowledge base is intentionally small and synthetic. Evaluation currently consists of a limited set of manually tested questions.

A production implementation would require larger-scale document ingestion, stronger evaluation, access controls, retrieval monitoring and additional security safeguards.

10

NEXT STEPS

From prototype to enterprise-ready retrieval.

Future iterations could introduce persistent vector storage, document metadata, source-level citations, retrieval evaluation and a conversational user interface.

The evaluation suite could also be expanded with larger question sets to measure retrieval quality and grounded answer accuracy systematically.
